# CRM + Excel Data Consolidation Pipeline

An ETL pipeline that consolidates data from **three different sources** (a CRM export, regional Excel
workbooks and a JSON product catalogue) into **one centralized SQLite warehouse**, validates its accuracy
and produces an automated data-quality report.

> Built to mirror a common business need: many scattered sources, one reliable source of truth for
> management reporting. All data is synthetic and generated by the project.

## Architecture

```
crm_contacts.csv ──┐
sales_north.xlsx ──┼─►  Extract ─► Clean/Standardise ─► Validate ─► Load (SQLite star schema) ─► Quality report
sales_south.xlsx ──┤
product_catalogue.json ┘
```

**Warehouse schema:** `dim_customer`, `dim_product`, `fact_sales` (with primary and foreign keys).

## What the pipeline handles

| Problem in raw data | How it is handled |
|---|---|
| Duplicate CRM customers | De-duplicated on `customer_id` |
| Mixed date formats (`2024-01-05`, `05/01/2024`, `Jan 05, 2024`) | Parsed with multi-format fallback |
| Inconsistent country values (`NEPAL`, `np`, `Nepal`) | Mapped to one standard value |
| Different column names per regional Excel file | Column-mapping layer |
| Invalid quantities, orphan customer keys, unknown SKUs | Detected, counted and excluded |
| Trust in the final numbers | Reconciliation check: warehouse revenue = cleaned source revenue |

## Run it

```bash
pip install -r requirements.txt
python main.py          # generates sample data, runs the pipeline, prints results
pytest                  # unit tests
```

Outputs: `data/processed/warehouse.db` and `reports/data_quality_report.md`.

## Example result

- 315 raw CRM rows → 300 unique customers (15 duplicates removed)
- 1,700 raw sales rows → 1,652 validated rows (22 invalid quantities, 26 orphan-customer rows excluded)
- 6/6 validation checks passed
